Dayu-SDM 日志标准

统一事件表 sdm_event：一张表装所有厂商、所有类型的安全事件。 一个事件 = 一段元数据 + 一组角色 + 若干行为维度 + 一份告警声明 + 扩展区。

Design Principles

设计原则

三条边界贯穿全部 504 个逻辑字段与 53 个物理列：声明与事实分离、观测不等于攻防、投影不是权威。

PRINCIPLE 01

声明与事实分离

设备检测结论进 source_finding；客观行为事实进 roles / facets。一条日志既是行为又有检测判断时，两区各写各的。

PRINCIPLE 02

观测角色 ≠ 攻防角色

source / target 只表达观测方向；attacker / victim 仅在源告警明确声明时在 source_finding 中构造。

PRINCIPLE 03

投影是加速，不是权威

标量列是查询加速投影；权威值保存在四个 VARIANT 完整对象列。同一语义两处出现，写入端必须保证可复现一致。

Five-Layer Model

五层模型全景

逻辑上事件由五个对象区 + 扩展区组成；物理上落成 51 个核心标量投影列 + 4 个 VARIANT 完整对象列。 顶层标量是检索入口，对象列是权威存储。

metadataMETADATA –字段 接入来源、时间、标识和治理信息：租户、event_id、mapping_id、来源厂商 / 产品 / 实例、原始日志编号与原文。
eventEVENT –字段 事件种类、领域、行为、结果和严重度：record_kind、event_domain、event_type、operation、outcome、severity。
rolesROLES –字段 谁 通过什么 对谁 做了什么 + 关联实体：source、carriers[]、target、related[]、observer 五类观测角色。
facetsFACETS –字段 行为怎么发生的细节维度：network、http、dns、email、file、process、authentication、registry、application、container。
source_findingDECLARATION –字段 设备怎么认定的（告警声明）：标题、等级、分类、规则、ATT&CK、攻防双方、指标与漏洞、处置与判定结论。
extensionsEXTENSION 19Profile 路径 装不下的才进扩展区：source_private（私有扩展）、profiles（资产画像）、enrichments（富化）、unmapped（未映射）。
时间与身份

Unix 毫秒 · 两列身份

时间统一 Unix 毫秒 UTC。event_id 是标准化事件唯一标识（平台分配，与 raw_log 1:1）；log_id 是原始日志身份——来源有稳定 ID 填来源 ID，否则与 event_id 相同。

原文与引用

独立 raw_log 表

原文在独立 raw_log 表，经 event_id 1:1 关联，不参与字段映射。

对象去重

ref_id 关联

同一实体只建一个主对象，其他位置用 ref_id（如 process::xxx）关联，不在多个角色下重复构造。

Projection & Authority

标量投影与权威对象

Kafka 消息与 Doris 表都采用「标量投影 + 权威对象」混合结构：逻辑 Schema 决定字段含义， projection registry 决定哪些路径成为顶层标量。两个位置表达同一语义，必须一致。

索引策略

V3 倒排承接低频路径

roles_obj / facets_obj / source_finding_obj 建倒排索引承接低频标量路径过滤；extensions_obj 不建无约束全路径索引；数组任意成员查询不依赖下标方案。

13 个降级路径

低频投影退回对象

已通过 Doris 路径查询验证的 13 个低频标量投影降级到 roles_obj / facets_obj 权威存储，逻辑路径保留、物理列不建。

一致性要求 · 写入端必须保证
  1. 同源 — 标量投影来源于本条消息的权威逻辑对象，不能由另一套独立映射产生。
  2. DIRECT 相等 — 单值 DIRECT 投影必须与对象值相等。
  3. 可复现 — NORMALIZED / DERIVED 投影必须能按注册规则从对象值复现。
  4. 主值稳定 — PRIMARY_ONLY 必须使用注册的主值选择规则，不依赖数组偶然顺序。
  5. 不凭空造值 — 对象值缺失时不生成对应标量投影；补充值必须同时带允许的富化来源。
物理投影契约 · projection-registry.v1.json
53 列 Doris 投影的唯一机器依据；原文分离存储在 raw_log 表（006），事件与原文经 event_id 1:1 关联。
Roles & Declaration

角色区与告警声明区

roles 回答「谁对谁做了什么」，source_finding 回答「设备怎么认定的」。 两区语义独立：一条被判定为攻击的行为日志，roles 里只有观测到的 source 与 target。

观测角色可放对象要点
source 发起方host、process、user、account、endpoint、geo、resource观测到的发起方，不自动等于攻击者
carriers[] 载体process、script、resource行为链主载体；物理投影为 carrier_process_*
target 被作用方host、process、file、user、account、domain、url、endpoint、service、geo、resource观测到的被作用方，不自动等于受害者
related[] 关联实体上述对象皆可带 relation_type（父进程、关联主机…）
observer 观测设备product、device、resource采集或观察事件的产品与设备

record_kind

finding 是声明

record_kind=finding 表示来源设备的检测记录；activity 是行为活动。声明真假由下游研判，不在日志层判定。

severity 分轨

两套严重度不混用

event.severity 用 syslog 八级；来源告警的高 / 中 / 低危写 source_finding.severity，不机械投影。

声明即投影入口

声明 → 检出投影

设备检测声明保存在 source_finding_obj；来源告警接入路径把它投影为平台告警 SOURCE_ALERT，完整机制见 alert-model 文档。

使用约束

路径含 [] 表示数组对象或数组值，叶子按每个成员解释；必填依据当前 JSON Schema，事件类型契约可增加条件必填；样例仅说明值形态，不构成枚举或默认值。

Profile 边界

extensions.profiles.endpoint_asset 由 Profile registry v2 单独治理（19 条路径），表达终端资产相对 host 的增量快照，不计入 504 条核心路径。

Enums & Dictionaries

枚举与受控字典

闭合枚举只能写入目录列出的值；开放字段推荐值经评审扩展。 event.type + event.operation 是 105 项受控字典，未登记组合的 operation 必须留空。

事件类型字典 · event.type × event.operation

「—」表示该事件类型不允许填写 operation；已废弃类型只读兼容，新数据禁止写入。

写入规则

标准枚举统一小写；event.outcome 不保存阻断动作（来源 blocked 按语义映射为 denied）；未登记组合的 operation 留空；开放字段新增推荐值须更新契约，不允许单个接入规则自由造词。
